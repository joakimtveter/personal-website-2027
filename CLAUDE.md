# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Personal website built on **Payload CMS 4 (beta)** running inside **TanStack Start** (Vite 8 + React 19 RSC), backed by **Postgres** via `@payloadcms/db-vercel-postgres`. Package manager is pnpm; Node >= 24.22.1.

For any Payload-related work (collections, fields, hooks, access control, Local API, plugins), read the skill at `node_modules/payload/skills/payload/SKILL.md` first. Payload 4 is a beta, so APIs may differ from what you remember of Payload 3.

## Commands

```bash
pnpm dev                 # Vite dev server on http://localhost:3000 (admin at /admin)
pnpm devsafe             # same, after wiping dist/
pnpm build               # production build (payload build -> dist/)
pnpm start               # serve the production build with srvx
pnpm lint                # eslint
npx oxfmt                # formatter (no script; config in oxfmt.config.ts)

pnpm test                # int + e2e
pnpm test:int            # vitest, tests/int/**/*.int.spec.ts (jsdom)
pnpm test:e2e            # playwright, tests/e2e; starts/reuses `pnpm dev` on :3000

pnpm generate:types      # regenerate src/payload-types.ts after changing collections/fields
pnpm generate:importmap  # regenerate src/app/_payload/importMap.js after adding custom admin components
```

Single test: `pnpm test:int tests/int/api.int.spec.ts -t "fetches users"` or `pnpm test:e2e tests/e2e/admin.e2e.spec.ts -g "dashboard"`.

Both test suites talk to the real database configured in `.env` (int tests call `getPayload` directly; e2e seeds and deletes a `dev@payloadcms.com` user).

## Environment

Required in `.env`: `POSTGRES_URL`, `PAYLOAD_SECRET`. `docker compose up -d` starts a local Postgres whose user/password/database come from `POSTGRES_USER`/`POSTGRES_PASSWORD`/`POSTGRES_DB` in `.env` (these must match `POSTGRES_URL`); the app itself runs on the host. The adapter uses a plain `pg` pool only when the `POSTGRES_URL` hostname is exactly `localhost` or `127.0.0.1`; any other host goes through `@vercel/postgres` (Neon serverless driver), which won't work against an ordinary Postgres server.

## Architecture

- `src/payload.config.ts` is the single Payload config (aliased as `@payload-config`; `@/*` maps to `src/*`). Collections live in `src/collections/` and must be registered there. The MCP plugin (`@payloadcms/plugin-mcp`) and a single `en` locale are configured here.
- `vite.config.ts` wraps the Vite config in `withPayload(...)` from `@payloadcms/tanstack-start`, which wires up the RSC, TanStack Start and React plugins.
- Routing is TanStack file-based routing rooted at `src/app/` (`src/routeTree.gen.ts` is generated; don't edit it). Two pathless layout groups split the app:
  - `_frontend` — the public site. Pages go in `src/app/_frontend/`, global styles in `_frontend/styles.css`.
  - `_payload` — admin panel (`admin.index.tsx`, `admin.$.tsx`) and REST/GraphQL API (`api.$.ts`), all delegating to Payload via server functions in `_payload/server.functions.ts`. These files are generated by Payload ("MODIFY AT YOUR OWN RISK"); admin style overrides go in `_payload/custom.css`.
- `src/router.tsx` creates the router using Payload's search param parse/stringify helpers; `src/app/__root.tsx` wraps the HTML shell with `withPayloadRoot`.
- Generated files, excluded from lint and format: `src/payload-types.ts`, `src/routeTree.gen.ts`, `src/app/_payload/importMap.js`.

## Code style

oxfmt: no semicolons, single quotes, trailing commas, 100-char width. ESLint unused-var rules ignore names prefixed with `_`.
