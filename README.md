# Personal website

A bilingual (Norwegian bokmål and English) website built with Payload CMS 4 running inside TanStack Start. The content model and frontend are a port of Payload's Next.js [website template](https://github.com/payloadcms/payload/tree/main/templates/website) to TanStack Start.

The app uses Postgres through `@payloadcms/db-vercel-postgres`, which reads its connection string from `POSTGRES_URL`.

## Local setup

1. `cp .env.example .env` to copy the example environment variables, then set `PAYLOAD_SECRET` and `PREVIEW_SECRET` to random strings.
2. Start a Postgres database. The easiest way is `docker compose up -d`, which runs Postgres 17 on port 5432 and matches the `POSTGRES_URL` in `.env.example`. To use your own Postgres instead, point `POSTGRES_URL` at it.
3. `pnpm install && pnpm dev` to install dependencies and start the dev server.
4. Open `http://localhost:3000/admin`, create your first admin user, and use the **Seed your database** button on the dashboard to load demo pages, posts, a contact form and navigation.

Keep the database host in `POSTGRES_URL` as `localhost` or `127.0.0.1` for local databases. For any other host, the adapter connects through `@vercel/postgres` (Neon's serverless driver) instead of a plain `pg` connection.

### Environment variables

| Variable         | Purpose                                                                            |
| ---------------- | ---------------------------------------------------------------------------------- |
| `POSTGRES_URL`   | Database connection string                                                         |
| `PAYLOAD_SECRET` | Encrypts auth tokens                                                               |
| `SERVER_URL`     | Public URL of the site, used for CORS, canonical and Open Graph URLs and sitemaps  |
| `PREVIEW_SECRET` | Required for the admin panel's preview and live preview                            |
| `CRON_SECRET`    | Optional bearer token that lets an external scheduler call `/api/payload-jobs/run` |

## Production

Run `pnpm build && pnpm start` (or build the `Dockerfile`).

In development, Payload pushes schema changes straight to the database. Production applies the migrations in `src/migrations` on startup instead, so after changing collections or fields, run `pnpm payload migrate:create <name>` and commit the generated files.

Pages are rendered on the server for every request and sent with `Cache-Control: public, s-maxage=60, stale-while-revalidate=600`, so a CDN in front of the app can cache them briefly. Draft previews are sent with `private, no-store`.

## How it works

### Languages

There are two locales, `nb` (default) and `en`, defined in `src/i18n/locales.ts`. Every frontend URL starts with the locale (`/nb/...`, `/en/...`): `/` redirects to the visitor's preferred language, and paths without a locale redirect to the default one. Text fields are localized; slugs and structure (blocks, links, images) are shared between languages.

Publishing is per locale: a page or post only appears in a language once it has been published in that language. The language switcher, `hreflang` links and sitemaps only point to languages a document is published in.

Fixed interface text (buttons, labels) lives in `src/i18n/messages.ts`.

### Collections and globals

- **Pages**: layout-builder pages with a hero, blocks (call to action, content columns, media, archive, form) and SEO fields
- **Posts**: blog posts with rich text (including banner, code and media blocks), categories, authors and related posts
- **Media**: uploads with localized alt text and captions, a focal point, and responsive variants generated by sharp
- **Categories**: nestable post categories
- **Users**: admin users
- **Header / Footer**: navigation links

Plugins add **Forms** and **Form Submissions** (form builder), **Redirects**, **Search Results** (search index of posts) and SEO fields. Pages and posts have drafts, autosave, live preview and scheduled publishing; scheduled jobs run inside the server process every minute.

Custom URLs in links may be written without a locale (`/posts`); they are prefixed with the current locale when rendered. Redirects must include the locale (`/nb/old-page`).
